          This workspace comes pre-loaded with a realistic PDIA case study — a municipal team tackling low water access in informal settlements. Use it to learn the PDIA methodology, test every management framework, and understand how to follow up on findings.
          🌍 SDG 6 — Clean Water 🏛️ Urban Governance 🔄 3 Iterations Active 📊 12 Frameworks Populated

          In this case, a municipal WASH team is using PDIA to tackle chronic water access failure in three informal settlements (Westgate, Northridge, Lakeside). The team doesn't have all the answers — they're learning by doing, testing small experiments, and iterating based on evidence. That's the PDIA way.

          routeHow to Follow Up on Each FindingAction guide
          1
          🔴 Iteration 2 Finding: Rocky Terrain & Sensor Gaps
          Installation took 3× longer due to rocky substrate in Zone B. IoT sensors fail in Zone C (no mobile coverage).
          Follow-up Actions:
          • → Go to Task Manager — Task "Deploy LoRaWAN sensors in Zone C" is queued. Assign it.
          • → Go to Cause Analysis → 5 Whys — Drill into WHY the site survey missed rock substrate.
          • → Update PDCA → Check with actual installation time data vs hypothesis.
          • → Schedule Follow-up: "Phase 2 site survey review — include geological check".
          2
          🟡 Procurement Bottleneck: 14-Month Tender Cycle
          34-step process with 9 redundant gates. CFO sign-off is the critical chokepoint. Pre-qual framework is legally viable.
          Follow-up Actions:
          • → Go to Authority Map — Municipal CFO is marked "Neutral". Update strategy: address liability concerns.
          • → Go to Follow-ups — "Municipal CFO delegation policy" is OVERDUE. Reschedule urgently.
          • → Update OKR "Reduce tender cycle to <5 months" — currently at 15%. What's blocking?
          • → Add BSC → Internal Process metric: "Procurement steps eliminated (target: 9 of 34)".
          3
          🟢 Community Monitor Engagement Exceeded Expectations
          Community monitors reported 6 faults in week 1 — but need formal stipend and 24hr hotline to sustain engagement.
          Follow-up Actions:
          • → Go to Task Manager — "Finalise community monitor stipend policy" is OVERDUE (critical). Escalate.
          • → Go to PDCA → Act — Update with decision to scale monitor model to Phase 2 settlements.
          • → Go to Theory of Change — Add "24hr fault hotline" to Activities (currently missing).
          • → Update BSC → Customer: Add "Community monitor retention rate" KPI.
          4
          📊 OKR Tracking Shows Fault Response as Bright Spot (45%)
          Fault response time improvement is at 45% while household connection rate is only at 28% — IoT is working, installations are lagging.
          Follow-up Actions:
          • → Go to AI Coach — Ask: "My installation rate is lagging behind my sensor deployment. What PDIA entry points should I focus on?"
          • → Go to Goal Setting — Add monthly milestone: "8 standpipes installed per month" with tracking.
          • → Run Eisenhower Matrix — Q1 "Do Now": Resolve Zone C sensors and rocky terrain issues first.
          • → Schedule Weekly Review Wizard — step through GTD checklist to clear blockers.
          mapFramework Walkthrough — Recommended Learning Path
          Step 1 — Define the Problem
          Navigate to Problem & SMART. Review the pre-loaded problem statement. Edit the SMART goal fields to test the validator. Notice how the Dashboard hero updates automatically.
          Step 2 — Analyse Root Causes
          Navigate to Cause Analysis. Explore the Fishbone (6M) with 6 pre-loaded causes. Read the 5 Whys chain. Add your own cause — try adding a "Method" cause about the sensor deployment plan.
          Step 3 — Run Iterations
          Navigate to Iterations & PDCA. Read Iterations 1, 2, and 3. Update the PDCA "Check" field with what you learned. Create a new Iteration 4: "Scale community monitors to Northridge".
          Step 4 — Apply Frameworks
          Navigate to OKR · ToC · OGSM. Review the 2 OKRs and update their key result percentages. Navigate to BSC · SWOT — add a new threat you identify from the case context.
          Step 5 — Manage Execution
          Navigate to Task Manager. Move "Submit Q1 Ministry report" from Review to Done. Check the Dashboard to see how stats update. Add a new task for Iteration 4. Run the Eisenhower Matrix to prioritise.
          Step 6 — Review & Report
          Run the Weekly Review Wizard — step through the GTD checklist. Then navigate to Report & Export to generate the full PDIA progress report. Print it — it summarises all 12 frameworks.

          Problem & SMART Fishbone 5 Whys Cause Table

          The municipality knows water access is low, but PDIA demands rigorous diagnosis before action. You'll define the problem precisely, build a SMART goal, map root causes with a fishbone, and drill into the deepest cause using 5 Whys.

          01
          Write a precision problem statement Problem & SMART → Step 1
          Navigate to Problem & SMART. Fill in: Problem Statement (be specific — not "water is bad" but "only 23% of Westgate households have reliable piped access despite municipal mandate"), Context, Evidence of Impact, and What Success Looks Like. The form auto-saves as you type.
          02
          Set a SMART goal with the guided form SMART Goal Card
          Below the problem form is a SMART Goal builder with five labelled fields: Specific, Measurable (attach a KPI), Achievable, Relevant, Time-bound. As you complete all 5 fields, a SMART completeness indicator turns green. The completed goal renders as a formatted summary card referenced in reports. Demo: "Connect 50 standpipes in Westgate Phase 1 by December 2025, verified by IoT sensor uptime."
          03
          Map causes on the Ishikawa Fishbone Cause Analysis → Fishbone Tab
          Switch to Cause Analysis. On the Fishbone tab, causes are grouped into the 6M categories: Manpower, Method, Machine, Material, Measurement, Milieu. Click + Add Cause: enter Category, Root Cause, Evidence, and Controllability (High / Medium / Low — key for PDIA entry-point selection). The fishbone SVG auto-renders with bones extending from the "effect" head.
          04
          Filter & sort causes in the Interactive Table Table Tab
          Switch to the Table tab: a live-search box, a Category dropdown (filter by any 6M), and a Controllability dropdown. Click any column header to sort ascending/descending (⇅ icon). The count badge updates live. Each row has hover-reveal ✏️ edit and 🗑 delete buttons. Sorting by Controllability DESC reveals which causes you can actually act on.
          05
          Drill down with the 5 Whys chain 5 Whys Tab
          Switch to the 5 Whys tab. A vertical chain of 5 numbered fields walks through the Toyota method. Field 1 = "The Problem"; fields 2–4 = "Why?"; field 5 is highlighted green as "Root Cause → Actionable Entry Point". Click Save 5 Whys — the chain is referenced in the Weekly Review and Report Export. Example: Low access → No standpipes → Procurement blocked → 34-step approval → No pre-qual supplier framework.

          Execution Engine — Iterate, Track & Follow Through

          PDCA Iterations Task Kanban Goals Follow-ups

          expand_more
          🔄

          You've diagnosed the problem. PDIA doesn't mean a big plan — it means small, fast, deliberate experiments. Log a PDCA cycle, record the iteration, break it into tasks on a kanban board, track milestones in goal cards, and schedule follow-up meetings.

          01
          Fill in the PDCA Cycle canvas Iterations → PDCA Card
          A 2×2 PDCA canvas: PLAN (blue) — your hypothesis; DO (green) — the action; CHECK (amber) — what data; ACT (purple) — scale, pivot, or abandon. Each quadrant has a textarea. Click Save PDCA to persist. Example: Plan = "Install 3 LoRaWAN sensors in Zone C to test coverage"; Do = "Deploy Mon 10 Mar with IoT team"; Check = "Compare uptime vs SIM sensors over 2 weeks"; Act = "If >90% uptime, replace all 12."
          02
          Log a formal iteration on the timeline Timeline Tab
          Switch to the Timeline tab. A vertical timeline shows all iterations with colour-coded status nodes: 🔵 Doing, 🟡 Learning, 🟣 Adapting, 🟢 Done. Click + New Iteration to open the modal: Title, Hypothesis, Actions taken, Learning, Adaptation decision, Status, and Start/End dates. The demo has 3 pre-loaded iterations for Westgate standpipe deployment.
          03
          Manage tasks on the Kanban board or List view Task Manager
          Toggle between Board view (4-column kanban: To Do → In Progress → Review → Done) and List view. In Board view, cards are drag-and-drop — the column highlights on hover, and dropping auto-updates status. Each card shows a priority dot (🔴 Critical → 🟢 Low), a label chip, a due date (red if overdue, amber if today), and a circle checkbox. Click + Add Task for the full modal with iteration linking.
          04
          Track goals with milestone cards Goal Setting
          Goals appear as rich cards: a type badge (Annual / Quarterly / Monthly / Project), an animated progress bar, a due date chip, and an expandable milestone checklist. Check a milestone — the parent goal's % auto-updates. Add a new goal via + New Goal: enter milestones on separate lines. The demo has 3 goals: "50 standpipes" (45%), "Pre-Qual Framework" (30%), "Technician Training Cohort 1" (70%).
          05
          Schedule & track follow-up meetings Follow-ups
          Your meeting & commitment tracker. Each follow-up shows: title, agenda, due date (red if overdue), type chip (Stakeholder Meeting / Decision Point / Milestone Check / Iteration Review), priority, and a ✓ Done toggle. The sidebar badge counts open non-done follow-ups and turns amber when any are overdue. Demo: "Municipal CFO — Delegation policy sign-off" is 1 day overdue, triggering a notification bell alert.
          📌

          Linking tasks to iterations: The Link to Iteration dropdown in the task modal lists all saved iterations. This creates a traceable chain from your PDCA hypothesis all the way down to specific to-dos — great for weekly reviews.

          Strategic Frameworks — OKRs, BSC, SWOT & Eisenhower

          OKRs Theory of Change BSC SWOT Eisenhower Matrix

          expand_more
          📊

          Your project is running — now connect it to strategy. This example covers 5 built-in frameworks: OKRs for objective-setting, Theory of Change for impact logic, Balanced Scorecard for multi-perspective measurement, SWOT for honest self-assessment, and Eisenhower Matrix for ruthless prioritisation.

          01
          Build OKRs with Key Results tracking Frameworks → OKR Tab
          Click + Add Objective: enter an inspiring qualitative Objective and Quarter/Period. Add Key Results — each has a measurable outcome text and a % progress field. Saved objectives appear as OKR cards with gradient headers. Each KR row has an inline progress bar you can click to update. Overall objective % = average of all KRs.
          02
          Map your Theory of Change logic chain ToC Tab
          A 5-stage pipeline: Input → Activity → Output → Outcome → Impact. Click + Add Step, choose a stage, write a description, and add the underlying assumption. Steps render as colour-coded cards connected by arrows. Hover a step to reveal edit/delete. This makes your causal logic explicit and testable — a core PDIA discipline.
          03
          Build a Balanced Scorecard across 4 perspectives BSC · SWOT → BSC Tab
          Four coloured quadrants: 🔵 Financial, 🟢 Customer/Community, 🟠 Internal Process, 🟣 Learning & Growth. In each, click + Add Metric: enter Metric Name, Target, Current, and Status (🟢 On Track / 🟡 At Risk / 🔴 Off Track). Metrics render as rows with mini progress bars — giving you a strategic helicopter view across all four dimensions simultaneously.
          04
          Run a SWOT analysis with inline editing BSC · SWOT → SWOT Tab
          A 2×2 heatmap: 🟢 Strengths, 🔴 Weaknesses, 🔵 Opportunities, 🟡 Threats. Each quadrant has an inline-add bar — click the dashed box, type, press Enter. Items appear as translucent cards with hover-revealed delete buttons. No modal needed — designed for fast brainstorming. SWOT data flows into PDF export and Weekly Review.
          05
          Triage priorities with the Eisenhower Matrix Eisenhower Matrix
          Classic 4-quadrant layout: 🔴 Q1 Do Now (Urgent & Important), 🔵 Q2 Schedule (Not Urgent & Important), 🟡 Q3 Delegate, ⬜ Q4 Eliminate. Each quadrant has an inline text input — type and press Enter to add instantly. Items persist to storage. The demo pre-loads 12 items: "Get CFO delegation policy signed (OVERDUE)" correctly in Q1, "Redesign project logo" in Q4.
          🏆

          OKR best practice: Keep objectives inspiring and qualitative. Key Results must be strictly measurable — the app enforces a % completion field per KR to prevent vague outcomes.

          ⚠️

          Eisenhower tip: Most overachievers live in Q1 and Q3. PDIA asks: are your Q2 strategic items getting ignored? The matrix makes this imbalance visible at a glance.
